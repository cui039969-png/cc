# JSON 备份协议 v1

应用只读写本协议；不兼容 FrictionFreeDiary 或其他日记应用的数据库及备份。备份是明文 UTF-8 JSON，可能包含私人文本。文件由用户通过 Android 系统文件选择器选择，不申请存储根目录权限。

## 格式与边界

根对象必须且只能包含 `schemaVersion`（整数，固定为 `1`）、`exportedAt`（以 `Z` 结尾的 UTC ISO Instant 字符串）、`records`（数组）。字段不可缺失、为 `null` 或增加未知字段；重复 JSON 对象字段与超过 32 层的嵌套也被拒绝。

每条记录必须且只能含下列字段：

| 字段 | JSON 类型与语义 |
| --- | --- |
| `date` | 字符串；`yyyy-MM-dd` 真实日历日期，年份 0001–9999，按设备本地日期建立，不因后续时区变化改写 |
| `learned` | 字符串；今天学会了什么 |
| `unclear` | 字符串；尚未弄懂什么 |
| `nextPriority` | 字符串；明天优先解决什么 |
| `createdAt` | 非负的 64 位整数，UTC epoch 毫秒 |
| `updatedAt` | 64 位整数，UTC epoch 毫秒，必须大于或等于 `createdAt` |

每个回答最多 20000 个 Unicode 码点；一个扩展平面字符计为一个码点。文本须为有效 Unicode，不截断或替换坏字符。导入流最多读取 10 MiB + 1 字节检测超限，超过 10 MiB 整体拒绝；最多 10000 条，日期不得重复。导出也遵守相同数量与文件大小限制，按日期升序，保留全部文本、空白与元数据。

## 预览与写入

解析、结构、日期、长度与元数据校验全部通过后才显示预览：新增数量、冲突数量、冲突日期和异常数（通过校验时为 0）。坏文件直接显示安全的失败原因，数据库完全不变；不会显示私人原始 JSON。

默认跳过本地已有日期。用户选择覆盖且确认后，冲突日期使用导入记录的全部六字段，包括原始 `createdAt` / `updatedAt`。提交事务时重新检查冲突，所有写入共用数据库级互斥锁；任一插入失败整体回滚。相同文件默认重复导入幂等。预览或系统文件选择取消不产生写入。

导入前提交当前编辑并暂停编辑。成功后重新加载编辑页与历史，防止导入前的延迟输入覆盖新数据；真正提交成功且发生变化后通知组件刷新。导出选择文件后仍可能因文件提供方或磁盘失败留下不完整目标文件，此时界面报告失败，用户应重新导出。

## 纯虚构示例

以下不是用户记录。两个时间戳分别对应 2026-10-23 10:00:00Z 和 10:01:00Z。

```json
{
  "schemaVersion": 1,
  "exportedAt": "2026-10-24T10:00:00Z",
  "records": [
    {
      "date": "2026-10-23",
      "learned": "虚构：掌握函数单调性判断",
      "unclear": "虚构：参数分类讨论",
      "nextPriority": "虚构：完成两道练习",
      "createdAt": 1792749600000,
      "updatedAt": 1792749660000
    }
  ]
}
```

当前 Room 数据库为 v1，导出 schema 随源码维护；不使用破坏性迁移。尚无 v0 升级路线，不能把 v1 重开数据库测试称为跨版本迁移验证；以后修改 schema 时必须新增真实迁移及迁移测试。
